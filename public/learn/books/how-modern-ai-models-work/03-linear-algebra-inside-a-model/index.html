One piece of arithmetic, repeated

Lesson 0

Chapter 2 ended on a question. What actually happens when a token's 1,024 numbers meet a weight matrix, one of the grids of learned numbers inside the model? The answer is one piece of arithmetic, repeated all through the model. The model takes two lists of numbers, multiplies them pair by pair, and adds up the products. That one number scores how well the two lists match. Chapter 1's answer, Paris at 95 percent after "The capital of France is", is the best of 65,536 of those scores.

This chapter builds that multiply-and-add from nothing. It starts with why the model holds a word as a list of numbers at all. Each idea starts as code you already write, such as a loop over two arrays or an array of arrays. It runs first on a few small numbers you can see whole, and we say what the result means. Then the same idea runs on the real model, LiquidAI's LFM2.5-230M on a laptop CPU, as proof. Math has names for these ideas: vector, dot product, matrix, matrix multiplication, projection and transpose. Each name arrives after the thing it names.

Knowing that one piece of arithmetic pays off in three ways. You can say what any weight matrix computes and how long its output is before you run it. You can count how much arithmetic the model does for each token. And you can catch a real bug that no error message reports. At the end of the chapter, one square matrix read the wrong way round runs without an error, and the model stops saying Paris.

What you will be able to do#

  1. Say why a model holds a word as a list of numbers, not as text: text matching follows spelling, while the model's lists put related words close together, and the blocks then rework a word's list using the words around it.
  2. Write a dot product as a loop, and say what its answer means: a score for how well two lists match.
  3. Show that the model's score for Paris is one dot product of two lists of 1,024 numbers.
  4. Explain a matrix as an array of arrays and matrix multiplication as a nested loop, and show that the model's next word is the best match among the 65,536 rows of its output table.
  5. Explain how a matrix turns one list into another, show that all 83 of the model's weight matrices do exactly this, and show that the lists in a batch never mix inside one.
  6. Check that lengths line up, explain which side of a grid a list meets and why the code therefore reads a stored matrix on its side, and catch the square-matrix mistake that a length check misses.
  7. Count the work: one multiply-add per weight, per token.

3.4What the number means: a match score#

You are hereEvery weight matrix

Play the video: A match score

Watch · 1:46

A match score

Lesson 4

A dot product gives one number. To see what that number tells you, run the same loop three times against one list, q, and print the products next to each total:

The first list has the same signs as q in the same places, and every product is positive. The second has every sign flipped, and every product is negative. The third has a number only where q has a zero, so every product is zero.

Think of each pair as a vote. Two numbers with the same sign vote up. Two numbers with opposite signs vote down. A zero on either side does not vote. Bigger numbers cast bigger votes: in the match, the pair 2 and 3 adds 6, while the pair -1 and -2 adds only 2. The total of the votes is the score. Closeness, from the section on why lists beat text, is this same match score with each list first scaled to the same overall strength, so a list cannot score high only by holding big numbers. The lines marked "even out the sizes" in those scripts do that scaling. The model ranks its next word by the raw match score, not by closeness.

So a dot product is a match score. A large positive score means the two lists rise and fall together, number by number. A large negative score means they pull opposite ways. Zero means the votes balance, so overall they neither agree nor disagree. "Match" here describes the arithmetic only. It does not say two words mean the same thing.

Two wrong readings are common. The first is that the score counts equal numbers. In the match, the only equal pair is the two zeros, which add nothing, and the list still scores 8, because signs and sizes in the same places decide the score. The second is that a score of zero means something failed. Zero means the votes balance. Here no pair votes at all. In longer lists, up votes and down votes can also cancel out. Either way, the two lists neither agree nor disagree overall.

The model uses this because it needs one number for one question. Treat one list as a pattern. The dot product says how strongly another list shows it: strongly, not at all, or the opposite. The model asks that question everywhere, as the next sections show.

Check

Why the code flips the stored grid

Lesson 12

Flipping changes no number, so why would code ever need it? Because there are two ways to write the same nested loop. Grid first: for each row, pair the list with that row. Every loop in this chapter so far has worked that way. List first: for each column, pair the list with that column. The list's first number pairs with the grid's first row, its second number with the second row, and so on. So each answer runs down one column, and the list must be as long as a column. The script below runs both on the grid from flipgrid.py. Then it puts the list first against the same grid read on its side:

Grid first, the list [1, 0, 1] meets each row and gives two numbers, one per row. List first, the list [1, 1], two numbers because each column holds two, meets each column and gives three numbers, one per column. The last line puts [1, 0, 1] first against the flipped grid. The flipped grid's columns are the stored rows, so the list meets the stored rows again and gets [4, 10], the grid-first answer.

So the dot products are the same kind either way. The side decides whether the list meets rows or columns. To get the row answers with the list first, flip the grid.

Two facts about PyTorch make this matter for the model's code. First, PyTorch's nn.Linear creates its weight with one row per output number: w1 is stored as 2,560 rows of 1,024. Second, @ puts the list first: x @ W runs the list down each column of W. That list-first form is how math writes it, and PyTorch's @ keeps it. Code keeps the list first because the lists arrive stacked as rows, one per token, and list first hands each token's answer back in its own row, as batch.py showed.

Put the two together. Each column of the stored w1 runs down all 2,560 rows, so it holds 2,560 numbers, and a list of 1,024 cannot pair with it. That is the error from match.py. Read w1 on its side, as w1.T, and its columns are the stored rows, each 1,024 numbers long. Now every list meets every stored row, which is the nested loop we want. That is the last line of listfirst.py at full size. So the code for a weight matrix is x @ W.T, and PyTorch's own documentation writes the layer the same way.

rows.py showed this on the real matrix. Its first line printed W (2560, 1024), the stored layout, and its second printed x @ W.T equals the layer's output: True. The first two lines of match.py are the working version of the failed try. x @ w1.T gives (2, 6, 2560): two prompts, six tokens, 2,560 numbers each. Adding @ w2.T, also read on its side, brings each token back to 1,024.

This layout is PyTorch's. Other frameworks and file formats were not inspected here, and some may store matrices the other way round.

Check

Three, one per column: [5, 7, 9]. The list meets columns, and this grid has three of them.

A wrong reading of w1 stops with an error, because 1,024 and 2,560 differ. A square grid, with as many rows as columns, has the same size both ways round. The script below runs one list through a square grid of two rows of two, first as stored and then read on its side:

The model has 20 square weight matrices of 1,024 by 1,024: the output matrix of each of the 8 conv blocks, and the query and output matrices of each of the 6 attention blocks. Converting weights between formats, or writing the loop by hand, can make exactly this mistake. That is one matrix. We also flipped each of the 20 square matrices on its own: 11 kept Paris on top with less confidence, 9 changed the top answer, and in every case Paris fell below 95.2 percent.

A length check is necessary, and it is not enough. The check that catches this compares numbers. Run your code and a trusted reference on the same real input and compare the outputs. The reference must not share the part you suspect. If you converted the weights, the reference is the original model with its original weights, which is the comparison flip.py makes between its first and last lines. If you wrote the multiplication yourself, the reference is the library's own layer. A third check is to test with matrices whose two sizes differ, so a wrong reading crashes.

3.16Put it together#

You are hereThe whole machine

To the model, a word is a list of 1,024 numbers that training chose and nobody labelled. Words with related meanings have close lists, whatever their spelling, and the blocks rework a word's list with its context. A dot product is a loop over two lists of the same length: multiply each pair and add the products into one number. That number scores how well the lists match, because same-sign pairs vote up, opposite-sign pairs vote down and zeros do not vote. A score of zero means the votes balance. A matrix is an array of arrays, one row per question. Running a list against every row is a nested loop, and its answers form a new list as long as the number of rows. Every one of this model's 83 weight matrices does exactly that, including the output layer, whose 65,536 rows score every possible next word. Paris is on top because its row matches the last token's list best, with a score of 21. More lists only mean more turns of the outer loop, and they never mix. Each row must be as long as the list it meets. The side matters: with the grid first a list meets each row, and with the list first, as PyTorch's @ writes it, a list meets each column. PyTorch stores one row per output number, so the code reads the stored grid on its side, x @ W.T, whose columns are the stored rows. A square grid fits either way round, so only a comparison of numbers catches it being read backwards. And each weight costs one multiply-add per token, about 230 million per token here.

Every one of those numbers is stored in two bytes. Worked out with more precise numbers, the same Paris dot product comes to about 21.03, and the model kept 21. The next chapter asks what a number loses when it has only two bytes.

Terms · 20 in this chapter

weight matrix
A grid of numbers the model learned in training. Each row makes one output number and is as long as the list it takes in.
token
A small piece of text, often a word or part of one, that the model reads and writes one at a time.
scores
The raw numbers the output layer gives every possible next token, also called logits.
vector
A list of numbers. One token's 1,024 numbers are a vector. In code, a plain array.
embedding
The list of 1,024 numbers the model looks up for a token ID: one row of a big learned table.
closeness
A score for how alike two lists of numbers are. It runs from 1 (alike) through 0 (unrelated) to -1 (opposite).
context
The other words around a word in the same text.
dot product
Multiply two equal-length lists pair by pair, then add up the products. The one number you get scores how well the two lists match.
output layer
The last stage. It turns each token's numbers into a score for every token in the vocabulary.
block
One repeated stage that reworks every token's numbers. This model stacks 14 of them.
matrix
A grid of numbers, stored as an array of arrays. Each inner array is one row.
row
One inner array of a matrix. In a weight matrix, each row is as long as the input and makes one output number.
matrix multiplication
Running a list against every row of a matrix, one dot product per row: a nested loop. With several lists, every list meets every row.
vocabulary
Every token the model can score: 65,536 of them for this model.
projection
A weight matrix turning one list into a new list. Each row asks one question of the input, and each answer is one number of the new list.
batch
Several independent prompts stacked into one array, so one call handles them all.
column
The numbers at the same place in every row, read from top to bottom.
transpose
The same matrix read on its side: rows become columns and columns become rows. No number changes. Code writes it .T.
multiply-add
One multiplication added to a running total. A dot product of 1,024 pairs takes 1,024 of them.
parameters
The model's learned numbers, also called weights. Training sets them. Running the model only reads them.
