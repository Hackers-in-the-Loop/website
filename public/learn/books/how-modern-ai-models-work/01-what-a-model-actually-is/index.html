What's inside a language model

Lesson 0

You send prompts to language models every day, and text comes back. This chapter shows what runs in between. We use a real model, LiquidAI's LFM2.5-230M, a small open model with 229,693,184 learned numbers, and we ran it on a laptop CPU. We asked it What is the capital of France? Answer in one sentence. It replied The capital of France is Paris.

Three words carry most of the chapter. A tokenTerm tokenA small piece of text, often a word or part of one, that the model reads and writes one at a time. is a small piece of text, often a word or part of one, that the model reads and writes one at a time. A token IDTerm token idThe integer that stands for one token. The model only ever sees these numbers, never the text. is the integer that stands for one token. The model only ever sees these numbers, never the text. The tokenizerTerm tokenizerThe program that splits text into tokens and turns them into token IDs, and back again. is the program that splits text into tokens and turns them into token IDs, and back again.

Here is the whole machine. A language model is a function. Token IDs go in, and a probability for every possible next token comes out. A reply is that function called in a loop, one token at a time, until a stop token appears. Other things sit around the function: a chat template, sampling settings, a stop rule, and your app. They are not part of the model, yet they change the answer too.

Why learn the parts? When a reply surprises you, the cause can sit in any one of them. Often the cause is not the model at all but the template, a setting, or the stop rule. If you know the parts, you know where to look. The rest of the chapter goes through the machine one part at a time, with the real numbers from our run. It ends with a map of which later chapter covers each part in depth.

What you will be able to do#

  1. Say what the model function takes and returns, and read a real next-token distribution.
  2. Explain a reply as the function called in a loop that ends on a stop token, and say why greedy and sampled runs differ with the same numbers.
  3. Name the stages inside the function (tokenizer, embeddings, blocks, final norm, output layer) with the real shape at each.
  4. Say what the 229,693,184 parameters are, where they sit, and what "learned" means for them.
  5. Tell the model apart from the code and files around it, and show how they change what the model receives or what the user sees.
  6. Name the later chapter that covers each part.

Now call the model once and look at what comes back:

The model did not answer "Paris." It returned 65,536 scores, one for every entry in its vocabulary. A step called softmax turned those scores into probabilities: all positive, adding up to 1. Paris got 95.22 percent. The next four entries are other cities or pieces of city names, and together they get 1.6 percent. The other 65,531 entries share the remaining 3.2 percent. Note the leading space. The token Paris, ID 5242, is one piece that includes the space before the word.

That is all a language model does. A sequence of token IDs goes in, and a probability for every possible next token comes out. The raw scores are called logits. B1C05 covers how logits turn into probabilities, and what those probabilities do and do not mean.

The France prompt is unusually confident. An open-ended prompt spreads the probability across many tokens:

The top choice gets 35 percent, and the top five together get about half. Many continuations are plausible, and the probabilities show it.

Now send the France prompt again with one ID removed. The tokenizer normally puts a start-of-sequence token (BOS) at position 0, and its ID is 1. The --no-bos flag leaves it off:

Paris is gone from the top five. The user never typed the start token, yet removing it spread the probability out on this prompt. The two top picks are now <|im_end|>, which ends the turn, and a repeated is. The model cannot know which IDs you meant to send. It computes on exactly the IDs it receives.

Lesson 3

To produce a reply, call the function, pick a token, append it to the input, and call the function again. Stop when a stop token appears. The script below does this greedily, which means it always takes the most probable next token. It also prints the runner-up at each step. It sends the question the way a chat app does, through the model's chat templateTerm chat templateThe rule that wraps your messages in turn markers and special tokens before tokenizing, as a chat app does.. The chat template is the rule that wraps your messages in turn markers and special tokens before tokenizing. The section "What surrounds the model" covers it in detail.

Eight calls to the same function produced The capital of France is Paris. followed by <|im_end|>, the end-of-turn token, which has ID 7. The values printed as 1.000 and 0.000 are rounded to three decimals. Two things in this trace are easy to miss.

First, the model never decides to stop. At step 7 it gave <|im_end|> a probability that rounds to 1.000. The code line if ids[-1] == 7: break is what stopped the loop. The rule "ID 7 ends a reply" is written in code and in a settings file, not in the learned numbers. A loop that stopped on a different ID would keep going.

Second, this loop sends the whole sequence through the model at every step. The first call gets 21 IDs, the next gets 22, then 23. Resending everything keeps the code readable. A runtime can instead save intermediate results from earlier steps in a cache, so it does not recompute them. B1C09 covers the loop and the cache in full.

Greedy is only one way to pick. SamplingTerm samplingA picking rule that draws the next token at random, weighted by its probability. draws the next token at random, weighted by its probability. TemperatureTerm temperatureA sampling setting. Low values stay close to the top token, higher values spread the picks out. controls the spread. Low values stay close to the top token, and higher values spread the picks out. A repetition penaltyTerm repetition penaltyA setting that makes tokens already used less likely to be picked again. makes tokens already used less likely to be picked again. A seedTerm seedA number that fixes the random draws, so a sampled run repeats on the same software. fixes the random draws, so a sampled run repeats on the same software.

The model's repository ships its own picking rules in a settings fileTerm settings fileThe file shipped with a model that sets default picking rules and the stop token (generation config)., generation_config.json. Those rules sample at temperature 0.1 from the top 50 tokens, with a mild repetition penalty. The script below generates a coffee-shop slogan under three rules, with a random seed you choose. The off line overrides the repetition penalty from the settings file. The section "What surrounds the model" explains why that matters:

Command Tokens Slogan
python3 sample2.py greedy 8 "Where Coffee Meets Community"
python3 sample2.py shipped 0 17 "Where Coffee Meets Community: Your Perfect Spot to Sip and Connect!"
python3 sample2.py shipped 1 12 "Where Coffee Meets Community: Your Perfect Brew!"
python3 sample2.py shipped 2 17 same as seed 0
python3 sample2.py hot 0 10 "Brewed Beats for Comfort"

Every run ended on ID 7. Greedy stopped after four words. The shipped settings produced a longer slogan on every seed. Seeds 0 and 2 gave the same slogan, and seed 1 split off near the end. At temperature 1.0 the slogan was different from its first word on. A seed reproduces these exact results only on the same software stack.

Show the answer

None. The same 229,693,184 numbers produced all five slogans. Only the rule for picking and the random seed changed.

Inside the function

Lesson 5

Now follow the France prompt through the stages inside the function. The script below attaches a hook to every stage. Each hook prints the shape of the array that its stage produces:

The leading 1 in each shape means a batch of one prompt, and you can ignore it for now. Read the rest from top to bottom:

  • Tokenizer. The tokenizer turns the text into six IDs. The first is the start token, and the other five stand for the pieces of The capital of France is. The tokenizer works from a learned table of word pieces.
  • Embeddings. Each ID selects one row from a table that has 65,536 rows of 1,024 numbers each. That row is the token's embeddingTerm embeddingThe list of 1,024 numbers the model looks up for a token ID: one row of a big learned table.. A vector is a list of numbers, so the six IDs become six vectors of 1,024 numbers each.
  • Blocks. Fourteen blocks each take the six vectors and return six new vectors of the same size. Every block makes the same two moves. First it normalizes, runs a mixer, and adds the result back to its input. Then it normalizes again, runs a feed-forward part, and adds again. Normalizing rescales each token's numbers. The mixer is where tokens share information with each other. In the 8 convTerm convA mixer that blends each token with the two tokens just before it (short for convolution). blocks, each token's numbers are blended with those of the two tokens just before it. That operation is a short convolution, which is why these are called conv blocks. In the 6 attentionTerm attentionA mixer that lets each token pull information from every earlier token, weighted by content. blocks, each position takes a weighted combination of all earlier positions, with the weights computed from their content. The feed-forwardTerm feed-forwardThe part of a block that reworks each token's numbers on its own, widening them and narrowing back. part then transforms each position on its own, widening from 1,024 to 2,560 numbers and back.
  • Final norm. It rescales each position's vector after the last block.
  • Output layer. It scores each of the 65,536 vocabulary entries against the final vector. Only the row for the last position, the sixth, scores the next token. That is the row next.py read.

The shape stays (6, 1024) through all fourteen blocks. Only the output layer changes the width, from 1,024 to the vocabulary size. The mix of convolution and attention blocks is LFM2's hybrid design. The rest of the pipeline is common to the language models in this book: tokenizer, embeddings, a stack of blocks with mixers and feed-forward parts, final norm, and output layer. Later chapters point out where each model changes it. A few later models do not follow this pipeline at all. B1C19 covers a decision model that returns typed decisions instead of text. B1C20 covers an image generator, and B1C21 covers a diffusion model that does not write left to right.

Check

The input had six IDs and the output layer produced a (6, 65536) array. Why did next.py use only the last row?

Show the answer

Each row scores the token after its own position. The row at position 6 scores what comes after is, which is the token we want next.

Where the 229.7 million live

Lesson 6

The parametersTerm parametersThe model's learned numbers, also called weights. Training sets them. Running the model only reads them., also called weights, are the model's learned numbers. Training sets them, and running the model only reads them. They live inside the stages you just saw. They include the embedding table, the weights of every mixer and feed-forward part, and the small scale vectors in the norms. This script counts them by where they sit:

Nearly half the model is feed-forward parts. People usually name attention first when they describe these models, but the attention mixers are only 8.2 percent here. The embedding table alone is 29.2 percent. The last output line shows that the output layer has no weights of its own. It scores the vocabulary with the same 65,536-by-1,024 table that the embedding stage reads from. So the table is stored once and counted once. A separate output matrix of that size would add another 67,108,864 parameters.

While the model runs, the parameters sit in memory inside those layers. On disk, they sit in one file of 459 MB. Each parameter is stored in two bytes, in a 16-bit number format called BF16 (bfloat16). B1C04 covers number formats, and B1C11 covers how the file is laid out.

What does "learned" mean here? Liquid AI's model card says LFM2.5 "builds on the LFM2 architecture with extended pre-training and reinforcement learning," with a training budget of 19 trillion tokens. It says this 230M instruction model was "Distilled from LFM2.5-350M and refined with multi-stage reinforcement learning." In plain terms, Liquid AI trained these numbers on about 19 trillion tokens of text, then trained them further to follow instructions. B1C06 covers how training changes the numbers.

Several things that affect the reply are not parameters. They are the tokenizer's table of word pieces, the chat template, the sampling settings, the stop rule, the vectors computed during a call, and the cache a runtime keeps between steps of the loop. The vectors computed during a call are called activations. None of these is among the 229,693,184 learned numbers.

Check

The embedding table is 29.2 percent of the parameters. Why is it counted once when both the embedding stage and the output layer use it?

Show the answer

Because it is one table used twice. The output layer's weight and the embedding weight share the same storage.

What surrounds the model

Lesson 7

Much of what decides a reply sits outside the model. The model computes on IDs. Other code and files decide which IDs it gets and what happens to the IDs the loop picks. Three facts from this model show how much that matters.

The chat template is part of the input. A chat app does not send your text as typed. It runs the message through a template that ships with the model. The template wraps the message in special tokensTerm special tokenA token that marks structure, like the start of text or the end of a turn, instead of words., tokens that mark structure, like the start of text or the end of a turn, instead of words. The script below prints the IDs for a question with and without the template, plus one more message that we come back to shortly:

The template turned the question's six IDs into fifteen. In order, they are a start token, a user-turn marker (ID 6), the role, the question, an end-of-turn marker (ID 7), and an opened assistant turn (6, 64015, 708) for the reply to fill. To see what those added tokens do, send the same text both ways:

The template alone changed the answer. Both runs used the same parameters and the same question. As plain text, the top picks are line breaks, which together take over 95 percent. Through the template, The gets 98.99 percent, the start of a sentence that answers the question. The France sentence-completion prompt shifts the same way. As plain text, The capital of France is puts 95.22 percent on Paris. Through the template, its first token is The, at 89.49 percent.

Typed text can fake a turn. The third line of the surround.py output comes from a user message that contains the typed text <|im_end|> and <|im_start|>assistant. The tokenizer turned that typed text into the real control IDs 7 and 6, in the middle of the message. So the model receives what looks like a finished user turn, followed by an assistant turn that already started with Sure. The app decides whether user text may produce control IDs. The parameters have no say.

Settings and the stop rule ship separately, and they apply even when you did not ask for them. The instruction model's generation_config.json holds the shipped sampling settings and the stop token. Transformers loads that file with the model and merges it into every generate() call:

The file's repetition penalty changes even a greedy run. Pass only dict(do_sample=False), and generate() returns the 17-token "Where Coffee Meets Community: Your Perfect Spot to Sip and Connect!". Also set the penalty back to 1.0, and true greedy returns the 8-token "Where Coffee Meets Community". Nobody asked for a repetition penalty. The settings file supplied one, and it more than doubled the length of the reply. Any argument your code passes to generate() overrides the file. That is why sample2.py passes repetition_penalty=1.0 for greedy.

The settings file can differ between related models. This instruction model has a base model, LFM2.5-230M-Base, a pre-trained version meant for fine-tuning. The base model's generation_config.json holds no sampling settings at all. So Transformers falls back to its documented defaults, which are greedy decoding and at most 20 new tokens. The stop rule is configuration too. ID 7 ended every generation in this chapter, and that rule is a line of configuration, not a learned number.

An app adds more on top. It supplies the system prompt, the chat history, and length limits. It handles streaming and parses output such as tool calls. It also decides whether control tokens are shown or hidden when IDs are turned back into text. Speed depends on the runtime and the hardware as well as on the model. B1C13 covers cost.

1.7Put it together#

You are hereThe whole machine

When you send a prompt, the app runs it through a chat template, and the tokenizer turns it into IDs. Then the model function runs. The IDs become vectors of 1,024 numbers, fourteen blocks transform them, and the output layer scores all 65,536 possible next tokens. A loop picks one token by a rule, appends it, and calls the function again. It stops when code sees the stop token. The model itself is the function and its 229,693,184 learned numbers. Nearly half of those numbers sit in feed-forward parts, and nearly a third sit in one table used at both ends. The template, the picking rule, the seed, the stop token, and the app are not the model. Most of them changed an answer in this chapter.

The next chapter starts with the shapes you just saw: (1, 6), (1, 6, 1024), and (1, 6, 65536). It explains what each axis means. It also shows how the parameters differ from the activations and the cache, which exist only while the model runs.
