What's inside a language model

Lesson 0

You type What is the capital of France? Answer in one sentence. into a small open model, and it replies The capital of France is Paris. What actually ran? This chapter answers that on a real model, LiquidAI's LFM2.5-230M, which we ran on a laptop CPU.

Here is the answer in one paragraph. Your text is cut into numbered pieces. The model is a function that takes those numbers and gives every possible next piece a score. A separate step turns the scores into chances. A rule picks one piece, the piece is added to the input, and a loop repeats all of that until a stop piece comes up. Inside the function is a chain of stages that run on 229,693,184 stored numbers. Around the function sit files and code that nobody trained, and they change the answer too.

The chapter builds each part from nothing. Each idea starts as code you already write, such as a dictionary, a function or a loop. It runs first on a few made-up values you can see whole, and we say what the result means and why the model works that way. Then the same idea runs on the real model, as proof.

Knowing the parts tells you where to look when a reply surprises you, because the cause is often not in the learned numbers at all. In this chapter, one start token nobody typed, a chat template, and a settings file nobody opened each change what the model says.

The machine, in the order the chapter opens it:

  1. Text to IDs. A tokenizer cuts your text into pieces and swaps each piece for a number.
  2. IDs to scores. The model gives every possible next piece a score.
  3. Scores to chances. A step called softmax, run outside the model, turns the scores into probabilities.
  4. Chances to a reply. A rule picks one piece, and a loop repeats until a stop piece.
  5. Inside the model. A table lookup, 14 blocks and an output layer, all running on stored numbers.
  6. Around the model. A chat template, a settings file, a stop rule, and your app.

What you will be able to do#

  1. Say what goes into the model: text cut into tokens, each token an integer ID, with a start token nobody typed.
  2. Say what comes out: one score for each of the 65,536 tokens in the vocabulary, which softmax, a separate step, turns into probabilities; and say why a chance for every token fits better than one answer.
  3. Explain how a reply is built: a loop calls the model, picks one token by a rule (greedy, sampling, temperature), appends it, and stops when code sees the stop token.
  4. Trace a prompt through the stages inside: an ID picks a row of a learned table, 14 blocks share information between tokens and rework each token, and the output layer scores the vocabulary.
  5. Say what the 229,693,184 parameters are, where they live, and why running the model never changes them.
  6. Separate the model from the chat template, the settings file, the stop rule and the app, show how each one changes the reply, and name the later chapter that opens each part.

Scores become probabilities

Lesson 3

Scores of 21 and 15 are not percentages. One more step, which our code runs after the model returns, turns them into chances. SoftmaxTerm softmaxThe step that turns scores into probabilities that are all positive and add up to one. is the step that turns scores into probabilities that are all positive and add up to one. A probabilityTerm probabilityHow likely the model rates a token as the next one, from 0 to 1, shown here as a percent. is how likely the model rates a token as the next one, from 0 to 1, shown here as a percent.

In code, softmax is three steps you could write yourself. Turn every score into a positive number. Add those up. Divide each one by the total, so each becomes its share. The script below runs the three steps on the four scores from function.py:

Every share is positive, even for the score of -1, and the shares add up to 100 percent. The order is kept: the biggest score got the biggest share. To make each score positive, softmax raises the number e, about 2.72, to the power of the score. So a token with one more point of score gets about 2.7 times the share. Paris is two points ahead of Lyon and gets about 7.4 times its share. What decides the shares is the gap between scores, not their size.

Why turn scores into probabilities at all? A probability means the same thing on any prompt, and code can draw a token at random by its probability, as a later section does. Raw scores support neither.

The real scores go through the same step. torch.softmax is PyTorch's version of the three steps:

The score of 21.00 became 95.22 percent, and 15.88 became 0.57 percent. Paris leads the next token by about five points, and every point multiplies the share by about 2.7. That lead is enough for 95 percent. All 65,536 probabilities add up to 1.

A tempting reading is that a score of 21 means 21 percent. It does not. Scores here run from about -14 to 21. Only after softmax are they chances, and softmax runs in our code, not in the model.

Check

In softmax.py, what happens to the probabilities if every score goes up by 10?

Show the answer

Nothing. Only the gaps between scores decide the shares, and adding 10 to every score keeps every gap. We worked this out from how softmax is defined; we did not run it.

Chances, not an answer

Lesson 4

After softmax, Paris has 95 percent. So why does the model rate every token at all, instead of just saying Paris? There are three reasons, each visible in a real run. The script below prints the most likely next tokens and where the rest of the probability goes:

On the France prompt, Paris holds 95.22 percent. The next four split 1.6 percent, and the other 65,531 tokens share 3.2 percent. The model never says Paris. It says 95 percent Paris.

The first reason for chances is that many continuations can fit. After "I stayed up all night, so today I feel", the top pick, like, gets 35 percent. The obvious word, tired, comes eleventh at 1.6 percent. The top five hold about half the probability, and the other half is spread thin across everything else.

The second reason is that the chances show how sure the model is. Ninety-five percent Paris against 35 percent like says the first prompt has one clear continuation and the second has many.

The third reason is that the picking is left to code. The same chances can feed a rule that always takes the top token, or one that varies the reply, as the next sections show. Training uses the chances too. In the Transformers library, training a model like this one grades the probability it gave to the token that really came next. Chapter 6 opens training.

A tempting reading is that anything under 100 percent means the model is unsure or wrong. Every one of 65,536 tokens gets some share, so even Paris leaves about 3 percent spread over the rest.

A random draw took a 2 percent token. One number makes the draws bolder or safer. TemperatureTerm temperatureA number every score is divided by before softmax. Below 1, the top token gets even more of the probability. Above 1, the picks spread out.

In code, temperature is [s / t for s in scores], run before the softmax from earlier. The script below runs it on three made-up scores at three temperatures:

At 0.1, tired takes all but a sliver. The printed 100.0 percent is rounded: we calculated 99.995 percent. At 1 the shares are 66.5, 24.5 and 9.0 percent. At 2 they spread to 50.6, 30.7 and 18.6. Inside a block

Lesson 11

Each token now has its list. What do the 14 blocks do to those lists? Every block does two jobs. First, tokens share information with each other. Then each token is reworked on its own. Reworking means computing a new list of 1,024 numbers from the old one, with arithmetic on the block's own learned numbers. Chapter 3 shows that arithmetic. In code, a block is a function from six lists of 1,024 numbers to six lists of 1,024 numbers. Its first part reads across the lists. Its second part loops over them one at a time.

A mixerTerm mixerThe part of a block where tokens share information with each other. is the part of a block where tokens share information with each other. This model has two kinds:

  • A convTerm convA mixer that blends each token with the two tokens just before it (short for convolution). is a mixer that blends each token with the two tokens just before it (short for convolution). Each token's new list is made from its own list and the lists of the two tokens before it. The model has 8 conv blocks.
  • AttentionTerm attentionA mixer that lets each token pull information from every earlier token, weighted by content. is a mixer that lets each token pull information from every earlier token, weighted by content. The model has 6 attention blocks.

The inside.py output above lists them: blocks 0 and 1 are conv, then the two kinds alternate, and every block hands on six lists of 1,024 numbers.

Why share at all? A token's list starts out the same after any sentence, because it is looked up. Without sharing, is would be worked on the same way whatever came before it. The mixers are where the earlier tokens get in.

Attention's "weighted by content" means some earlier tokens count for more than others. In a separate run we recorded where the last token, is, drew from in the first attention block (block 2), averaged inside that block. About half came from the start token, 23 percent from The, and 1 percent from France. That is one block on one prompt, not a rule about what the model looks at.

After the mixer, the feed-forward part works on each token alone. The feed-forwardTerm feed-forwardThe part of a block that reworks each token's numbers on its own, widening them and narrowing back. is the part of a block that reworks each token's numbers on its own, widening them and narrowing back. Here it widens each list from 1,024 numbers to 2,560 and narrows it back to 1,024. Each job adds its new list onto the list that came in, number by number. Each job also starts by rescaling the token's list, as the final norm does at the end. Chapter 8 opens what each part computes.

In plain terms, Liquid AI says it trained these numbers on about 19 trillion tokens of text, then trained them further to follow instructions. Chapter 6 opens how training changes numbers.

Because running the model never changes them, the same stored numbers can serve every user and every prompt. On disk, they are one file of about 460 megabytes. Chapter 4 opens how many bytes each number takes.

A tempting belief is that the model learns from your chats as you use it. Not this model in this code: no number changed. An app could store chats and train on them later, and that happens outside the model.

The settings file supplied one, and it more than doubled the reply. The script below shows how, at the step where the two runs part:

Greedy picks the top score. After "Where Coffee Meets Community", the closing quote led the colon by under one point. The quote had already been used, as the slogan's opening mark, so the penalty divided its score by 1.05. That took a little over one point off, down to 21.79, and the colon came out on top. Greedy took the colon, and the slogan kept going. With the penalty off, the quote wins, and the slogan closes at 8 tokens.

A tempting belief is that a repetition penalty bans repeats. It nudged one score by about 5 percent, and that flipped the pick only because the race was close. Publishers ship defaults like this to cut down on repeated words; the model card does not explain this particular value.

The settings file can differ between related models. This instruction model has a base model, LFM2.5-230M-Base, a pre-trained version meant for fine-tuning. Its settings file holds no picking settings at all, so Transformers falls back to its documented defaults: greedy, and at most 20 new tokens. The stop rule is configuration too. ID 7 ended every generation in this chapter, and that rule is a line in the settings file and in code, not a learned number.

An app adds more on top. It supplies the system prompt, the chat history and length limits, handles streaming, parses output such as tool calls, and decides whether control tokens are shown when IDs turn back into text. When a reply surprises you, read the settings actually in effect before you blame the learned numbers.

1.17Put it together#

You are hereThe whole machine

A tokenizer cuts your text into tokens and turns each into an ID, adding a start token you never typed. The model is a function: the IDs go in, and one score for every token in its vocabulary comes out. Softmax, a step our code runs, turns the scores into probabilities that add up to one. Scores and chances are not an answer, so a loop picks one token, appends it and calls again until the stop token appears, and code decides to stop. Greedy takes the top token, sampling draws by the chances, and temperature sharpens or flattens them first without changing their order. Inside the function, each ID picks one row of a learned table, 14 blocks let tokens share information and then rework each token, and the output layer scores the vocabulary. The 229,693,184 parameters are the stored numbers those stages read, and running the model never changes them. Nearly half sit in feed-forward parts, and nearly a third in one table used at both ends. The chat template, the settings file, the stop rule and your app sit around the function, were never trained, and still changed replies in this chapter.

Every number in this machine sits in an array: the stored parameters, the lists each stage hands on, the IDs the loop grows step by step. Which arrays did training make, which are made fresh for one call, and which are kept from one step of a reply to the next? The next chapter answers that.

Terms · 31 in this chapter

model
A function: token IDs go in, a score for every possible next token comes out.
token
A small piece of text, often a word or part of one, that the model reads and writes one at a time.
tokenizer
The program that splits text into tokens and turns them into token IDs, and back again.
token id
The integer that stands for one token. The model only ever sees these numbers, never the text.
scores
The raw numbers the output layer gives every possible next token, also called logits.
softmax
The step that turns scores into probabilities that are all positive and add up to one.
probability
How likely the model rates a token as the next one, from 0 to 1, shown here as a percent.
stop token
The token that ends a reply. Here it is ID 7, the end-of-turn marker. Code watches for it.
parameters
The model's learned numbers, also called weights. Training sets them. Running the model only reads them.
start token
A special token, ID 1, placed before your text to mark the start of a sequence.
vocabulary
Every token the model can score: 65,536 of them for this model.
loop
Call the model, pick one token, append it to the input, and call again, until a stop token appears.
settings file
The file shipped with a model that sets default picking rules and the stop token (generation config).
greedy
A picking rule that always takes the most probable next token.
sampling
A picking rule that draws the next token at random, weighted by its probability.
seed
A number that fixes the random draws, so a sampled run repeats on the same software.
top-k
A sampling setting that keeps only the k most probable tokens and draws from those. The shipped settings keep 50.
temperature
A number every score is divided by before softmax. Below 1, the top token gets even more of the probability. Above 1, the picks spread out.
repetition penalty
A setting that lowers the score of every token already in the text, so it is less likely to be picked again. Here a positive score is divided by 1.05.
pipeline
A chain of stages in which each stage's output is the next stage's input.
embedding
The list of 1,024 numbers the model looks up for a token ID: one row of a big learned table.
block
One repeated stage that reworks every token's numbers. This model stacks 14 of them.
final norm
A last rescaling of each token's numbers, after the final block.
output layer
The last stage. It turns each token's numbers into a score for every token in the vocabulary.
mixer
The part of a block where tokens share information with each other.
conv
A mixer that blends each token with the two tokens just before it (short for convolution).
attention
A mixer that lets each token pull information from every earlier token, weighted by content.
feed-forward
The part of a block that reworks each token's numbers on its own, widening them and narrowing back.
weights
Another name for parameters: the model's learned numbers.
chat template
The rule that wraps your messages in turn markers and special tokens before tokenizing, as a chat app does.
special token
A token that marks structure, like the start of text or the end of a turn, instead of words.

Watch 17 short lessons, one idea each

▶Watch all 17 in order on YouTube

  1. Lesson 0

    What's inside a language model

    When you send a prompt, a tokenizer turns your text into token IDs, the model gives every possible next token a score, softmax turns the scores into chances, one token is picked and appended, and that repeats until a stop token; these lessons open each part on a real model.

  2. Lesson 1

    Text becomes token IDs

    The model never sees your text: a tokenizer cuts it into tokens, swaps each one for an integer ID, and adds a start token nobody typed.

  3. Lesson 2

    A model is a function

    A language model is a function: token IDs go in, and one score for every token in its vocabulary comes out; the same IDs give the same scores.

  4. Lesson 3

    Scores become probabilities

    Softmax, a step our code runs outside the model, turns scores into probabilities: every one positive, all of them adding up to one, and the gap between scores deciding the shares.

  5. Lesson 4

    Chances, not an answer

    The model scores every token and softmax turns the scores into a chance for every token, not one answer; that fits because many next tokens can fit, because the chances show how sure the model is, and because the picking is left to code.

  6. Lesson 5

    A reply is a loop

    A reply is the model function called repeatedly, appending one chosen token each time, and code stops the loop when ID 7 appears.

  7. Lesson 6

    Greedy or a random draw

    The rule that picks each token is yours: greedy always takes the top token, and sampling draws at random, weighted by the chances, so a less likely token comes up at its rate.

  8. Lesson 7

    Temperature

    Temperature is one number every score is divided by before softmax: below one it hands nearly all the chance to the top token, above one it spreads the chances out, and it never changes which token is on top.

  9. Lesson 8

    One missing token

    The function computes on exactly the IDs it receives: on the France prompt, dropping the start token nobody typed moved Paris out of the top five.

  10. Lesson 9

    A pipeline of stages

    Inside the function is a pipeline, each stage's output the next one's input: one list of 1,024 numbers per token through every stage, until the output layer turns them into a score for every token in the vocabulary.

  11. Lesson 10

    An ID picks a row

    The embedding stage is a lookup: each ID picks one row of a big learned table, that row is the token's list of 1,024 numbers, and no arithmetic happens.

  12. Lesson 11

    Inside a block

    Each of the 14 blocks does two jobs: first a mixer lets tokens share information (conv blends each token with the two before it, attention lets each token draw on every earlier token), then the feed-forward part reworks each token on its own.

  13. Lesson 12

    The parameters are stored numbers

    The parameters are the 229,693,184 numbers the stages read: named arrays loaded from one file, set by training, and only read while the model runs.

  14. Lesson 13

    Where the 229.7 million live

    The 229,693,184 learned parameters are the numbers inside those stages; feed-forward parts hold nearly half, and one embedding table serves both ends of the model.

  15. Lesson 14

    The template is part of the input

    A chat template wraps your message in turn markers before tokenizing, which changes the IDs the model receives, and so the prediction.

  16. Lesson 15

    The settings file rides along

    A settings file ships with the model and is merged into every generate call; its repetition penalty lowers the score of every token already in the text, and that alone stretched a greedy slogan from 8 tokens to 17.

    The map

    Each part of the machine opens in a later chapter of this book.
